## 图形及权威证据

- Godot 4.7.2 Mono，Vulkan Forward+，RTX 3060 Laptop GPU。固定 60 FPS 两套预设共 58 个场景、116 次实际运行。逐条比较开启和关闭视觉覆盖，5676 个逻辑帧、22704 条权威记录一致。3704 张 FramePostDraw 图像可按提交版本追溯到同次 `trace.json` 和 `duel.log`。
- `local-mugen/stage16-validation/fixed-final/` 为主批次，`fixed-refined/` 为受击绑定、两段蹲防输入和多招场景复验；同名以复验为准。图集显示序列从真实 Manifest 验证。画面示例在 `fixed-overview.png` 和 `fixed-mode2-overview.png`，原始图像保存在每场 `sprite/frames/`。
- 实时 30 FPS 上限 `real30-final/` 采样状态 29、31、33、35。215 从首段停顿恢复并进入第二段，第二次接触后仍显示正确帧。实时 60 FPS 上限 `real60-warm/` 采样镜像 205 的命中停顿，`real60-thaw/` 在状态 34、35 见 5005 与模式 2 待机，状态 37、38 双方恢复待机。三次验收无帧积压告警。实际状态和绘制编号保留在文件名与同次日志中，见 `realtime-overview.png`。
- 与原引擎逐帧配对 50 个场景、1694 个归一化状态，未发现未解释差异。两套预设的中心距 44 对攻中，原版近重拳随机反击实扣 61，NewKOF 使用中心距 62 对攻实测的固定反击 54。其余比较项包括两个攻击时钟、攻击框、移动、独立停顿和恢复。阶段 14/15 与 13C 证据及各项测试日志在 `frozen-gates/`。

## 已确认的对照边界

- 轻拳同键按身体距离选择 205 或 200，重拳选择 215 或 210。原脚本轻拳在重拳前，在距 44 和 70 的同席双键输入中分别优先 205 和 200。近身动作两套预设的 Action 相同。
- State 205 的阶段长度为 3/4/5，State 215 为 3/10/15。近重拳的两个判定窗为招式 tick 3–5、6–12。原版 `MoveHitReset` 启用第二段，NewKOF 为这两个窗口配置两个接触组。各段独立结算，原始角色资源维持不变。受击姿态 205 为 5000→5005，215 为 5002→5007。每次实际命中重新开始受击姿态，随后按目标自己的停顿推进。
- 普通近重拳连续命中实际为 61、29，第一段落空而第二段单独命中为 69。两段格挡不扣血，松开后方向后仍可在首段硬直中防住第二段。蹲防后松开下方向可在第二次格挡时显示站防。反击样本的源脚本 RNG、防御缩放和反击状态延续仍是独立规则，当前伤害为已记录的固定投影。
- 原引擎的伤害在接触后的目标反应 tick 提交，NewKOF 在接触 tick 原子提交。对照分别检查这两个相位。接触前的守势走位和空中跳跃规则沿用各引擎自身契约。NewKOF 沿用帧开始朝向和默认推挤顺序，原版入招 `facep2` 及跨身后即时转向留作后续兼容性样本。蹲伏过渡的权威受击框取 MoveAudit，调试叠层的静态框只作画面参考。
- 首轮近轻拳空挥复现发现，通用空中受击框从脚点起算，覆盖了原始垂直跳跃素材留出的下方空隙。两套 Terry 配置读取 Action 41/49 共有的 Clsn2（X [−20,19]、Y [33,96]）。其他空中状态仍用既有受击框。中立跳输入按各引擎的跳跃时序触发，比较攻击方相对时钟与无接触结果。
- 两套预设的远转近对局在状态 20 同时出远身重拳和轻拳。随后另一席在状态 71 出近轻拳，状态 74 命中并打断刚进入的 215。近转远对局在状态 23 命中 205，击退将间距推过重拳近身边界，后续同席在状态 57 入 210，并按预设渲染 210 或 211。冻结中间的一次重拳输入未发动。
