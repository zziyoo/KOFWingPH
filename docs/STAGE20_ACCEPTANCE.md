## 验收矩阵

- **20A 原引擎 PASS**。比较 State 205 自身 AIR 与 State −2 的许可，分别核对旧 tick 4、5、6、提前输入、旧 tick 7 回落、旧 tick 12 普通启动和无手势拒绝。以已保存的原始动作事件和轨迹为准。
- **20B/C 复用与接入 PASS**。新预设将一条现有格式的 `CancelDefinition` 加入 205。来源由当前 `MoveDefinition` 决定。原有 200 规则、1000 招式、1020 实体、表现绑定及两条 205 轻拳重进按原值复用。
- **20D 多路径 PASS**。以当前身体距离区分近身和远身回落，核对同边沿只消费一次、非法候选无补发、旧实例攻击和确认清理。双席同时发生在同一对称距离时可走同一分支，不同来源由同场先后走位、格挡击退和出招验证。
- **20E 实体和暂停 PASS**。对两个来源进入的 1000 核对从 tick 0 启动、tick 15 出生、独立实体 ID、实际早晚段、削血、HitPause 与全局 Pause。打断、回合清理和同种子重放复用已冻结回归，并加入双席独立解冻专项。
- **20F/G 图形与回归 PASS**。固定帧覆盖完整状态，实时核对已绘制状态的顺序、画面及实体。实际 Godot 提交版本和同次 `FramePostDraw` 图像均保留。冻结阶段 13C–19 权威日志原样通过。
- **20H/I 兼容边界与交付 PASS**。保留历史语义差异、双预设独立配置、冻结标签和用户的项目配置差异。命令、原始日志目录及新阶段证据见下文。

阶段 19 的伤害相位、席位 RNG、反应受击框、连续防御、空中反应和起身投技保护边界继续适用。默认模式的两个取消来源共用目标，原版模式 2 的 State 1050 属于另一个目标与实体契约。 [阶段 19 验收](STAGE19_ACCEPTANCE.md)

原版近身空挥样本用对方垂直跳跃避开首招。NewKOF 单 tick 跳键采用短跳，重复原始跳键会让 205 在首生效帧命中。固定帧对照只调整防守者的跳键时长及提前量，保留发起者的所有输入和 `L=F+14`。`whiff-16/17` 的 Wave 接触时间、位置与实体年龄对应，接触时目标高度仍有差异。`whiff-18/19` 的 Wave 接触发生在地面。`whiff-20` 两引擎都回落至 205，第二次空中接触时机存在已测差异。

`hit-far-23` 的独立 205→200 重进在两边均合法。原版反应框让第二拳晚一 tick 接触。`guard-23`、`guard-far-23` 重进同为 205→200，后续独立接触沿用阶段 18 的续防差异。固定复现对差异的帧、事件、目标旧状态和 HP 单独断言。 [阶段 18 兼容性](STAGE18_COMPATIBILITY.md)
