# 阶段 18 兼容差异与阶段 19 交接

阶段 18 验收范围为 `TerryReentry`／`TerryReentryMode2` 站轻拳显式重进。三类已知差异分别落在目标受击框、防御硬直和动作末端普通选招。下列记录使用冻结版 `71155157438798ca8e58cdfc1561783f20935fcd` 的证据。原版 `F` 从首个有效对局帧计数，Godot `L` 为提交事件的逻辑帧，`R` 为渲染采样帧。前三组固定样本 `L=F+14`，`FramePostDraw` 的状态版本为 `L+1`。原版接触事件和下一反应帧扣血分别核对。 [阶段 18 验收](STAGE18_ACCEPTANCE.md) · [原版取证](STAGE18_REFERENCE.md)

- 阶段 19 可用独立的单次接触夹具验证进入 State 1000。1020 后续接触确实依赖原版反应框时，先取证反应种类、AIR 元素、冻结和世界坐标，再单独评估可选的权威反应框时间线。需覆盖镜像、受击重置、停顿恢复及旧配置回退，复跑旧门禁。直接把渲染帧或现有视觉反应时钟接入碰撞会把只读表现变成战斗输入。 [阶段 19 计划](superpowers/plans/2026-11-13-stage19-terry-special-cancel.md)

## 独立轻拳实例在防御硬直中命中

- **中心距 44，205→200。** P1 仍在 F5／F23 按 `x`，P2 从 F7 至 F40 按住后。Godot 是 R28／R46 各按 `J` 一 tick，P2 `Right` 从 R30 按至 R64 松开。原版 F8 格挡，F23 重进，F26 再格挡，两次均无削血。Godot L22 格挡且 HP1000，L37 重进，L39 对手仍为 `Blockstun(4)`，L40 转 `Hitstun` 并扣 44 至 HP956。相同输入在中心距 60 的 200→200 对照中，两边都先格挡、重进、第二击空挥。 [原版轨迹](../local-mugen/stage18-reference-canonical/results/default-reentry-near-guard-23.jsonl) · [Godot 日志](../local-mugen/stage18-validation/fixed-refined/default-reentry-near-guard-23/sprite/duel.log) · [Godot 第二击](../local-mugen/stage18-validation/fixed-refined/default-reentry-near-guard-23/sprite/frames/render-00050-state-00041.png) · [远身对照](../local-mugen/stage18-validation/fixed-v1/default-reentry-far-guard-23/sprite/duel.log)
- `ResolveSettlement` 仅在攻击发动帧与目标去重记录相同时沿用 `priorGroups`。这两次轻拳均为无分组的独立实例，`priorGroups=0`。`CanGuard` 允许按后待机、蹲伏及特定空防。`ResolveAttack` 允许既有分组招式的 Mid 后段在 `Blockstun` 中继续防御。本例缺少该分组资格，持续按后也不能格挡第二击。阶段 18 的首次格挡后显式重进仍通过，普通连防属于独立规则。 [接触实例与防御资格](../core/BattleCore/Simulation/BattleSimulation.cs#L1573)
- 阶段 19 先隔离验证格挡后的特殊技入口，再实测 1020 接触时目标是否已脱离防御硬直、方向是否仍保持。若后续实体门禁要求真实连防，独立审查配置范围、上下段、背向、松后、停顿和 215 已支持的多段自动续防。不要把第二个招式标为第一招的第二接触组，两个实例须维持独立的确认、去重和事件身份。 [阶段 19 计划](superpowers/plans/2026-11-13-stage19-terry-special-cancel.md)

## 普通收招终点的缓冲优先级

- **中心距 100。** P1 F5 `x`，F16 `y`，F17 `x`，P2 无输入。Godot 为 `J` R28–29、`K` R39–40、`J` R40–41。原版 F17 的旧时间 12、`AnimTime=0`、`var(2)=1`，根轻拳命令有效，Helper 的重拳值仍为 2。普通 CMD 顺序先检查 205／200，再检查 215／210，所以进入 200。原版两个预设和镜像共四场同样成立。Godot 默认预设 L30 仍为旧 200 的 Recovery tick 11，L31 启动 210。冻结证据有一场默认 Godot 差异复现，其他 Godot 预设和镜像未单独复现该差异。 [原版轨迹](../local-mugen/stage18-reference-terminal-priority/results/default-reentry-whiff-heavy16-light17.jsonl) · [Godot 日志](../local-mugen/stage18-validation/terminal-priority-observed/default-reentry-whiff-heavy16-light17/sprite/duel.log) · [Godot Action 210 首帧](../local-mugen/stage18-validation/terminal-priority-observed/default-reentry-whiff-heavy16-light17/sprite/frames/render-00041-state-00032.png)
- `RecognitionState` 只对当前帧同时可识别的候选用命令优先级，随后将胜者追加到缓冲。`FighterStateMachine.Tick` 进入普通启动时按缓冲先后遍历，前一帧的 5B 仍有效，先于本帧的 5A。这条分支发生在显式重进窗口 7–11 之后。F12 同帧 `x+y` 优先轻拳、F17 单独 `x` 正常启动，均已有独立通过证据。 [识别胜者与缓冲](../core/BattleCore/Commands/RecognitionState.cs#L209) · [普通启动消费](../core/BattleCore/Combat/FighterStateMachine.cs#L244)
- 原版弱 Power Wave 的 CMD 控制器先于站轻拳。阶段 19 若仅接入显式取消，先用 236A 与轻拳竞争的实测锁定局部选择。若自然结束也存在实际竞争，最小改动是给实验预设限定候选顺序，且只在有原版证据的入口启用。全局改 FIFO 会影响普通启动、未过期旧指令、同帧识别和其他角色的重放。 [弱 Power Wave 源审查](STAGE19_SOURCE_AUDIT.md)
