# 阶段 14：单招式战斗规则接入计划

> **For agentic workers:** Use superpowers:executing-plans to implement the units below and record the evidence at each gate.

**目标：** 用本地 Terry 的远距离站轻拳 State 200，完成从已核对的原始定义、权威招式执行和判定，到真实 Godot 表现的闭环。交付仅限可显式启用的单招式实验配置。

**架构：** 离线把经审阅的源规则转换为 NewKOF 已有的有类型招式数据。逻辑时序、判定框和命中结算由固定步长内核负责；表现用稳定 MoveId 映射 Action 200，并用已提交的 `MoveElapsedFrames` 取样。校验绑定与素材在离线完成，运行时战斗不读 Manifest。

**技术：** 现有 .NET 8 BattleCore、角色 JSON、离线 Python 工具和 Godot 4.7.2 Mono/Vulkan。13C 冻结基线见 [STAGE13C_FREEZE.md](../../STAGE13C_FREEZE.md)。阶段 14 启动前的项目文档没有既定阶段 14 计划。

## 复用与边界

- 复用 `CommandRecognizer` 的识别、`FighterStateMachine` 的行动许可与三阶段时钟、`FighterDataLoader` 的严格 schema v1、`FighterBoxes` 的定点矩形与镜像、`HitDetection`、D79 防御、D81 攻击实例去重、`BattleSimulation` 的结算及 D96 停顿、13C 已有视觉映射。现有 `CancelDefinition` 能表达对其他招式的确定窗口及命中/防御/空挥条件，无法直接表达原版的同招重进和脚本优先级。
- 当前全局受击框按姿态取通用矩形；`AttackDefinition` 使用单一对称 HitStop 值；没有通用 `HitDef`、`StateDef` 控制器解释器或 `hitflag` 多条件匹配。先为实验配置建立明确的数据边界。只有参考轨迹证明单招式必须扩展的能力，才安排单独评审和专项测试。
- 参考本地 IKEMEN GO `docs/combat-research/` 的 04、05、07、08、10、16、22、23、25。以文档声明的研究版本 `4d007d6e…`、`5dac5caf…` 为准。落实 D7 及 23 号文档的有类型动作数据路线，采用 05 的权威动作 tick/视觉分离原则。25 的 HitPause 及取消验证来自最小夹具，不能代替 Terry 参考轨迹。外部镜像只读。
- 阶段内仅做一招、一套明确条件的 1v1 地面命中/格挡/落空闭环。延后远近选择、完整 Terry、其他招式、同招及跨招脚本取消、AI 行为、脚本变量与 helper、能量与特殊模式、完整动作受击框、空中追击、通用 VM、联机。Kai/Rei 默认数据、帧调度、既有仲裁、快照版本与 13C 默认行为作为回归边界。第三方素材和原脚本不进入 Git。
